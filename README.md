# 合同管理系统 Contract Register

上传英文合同后，系统先在本机识别文字（扫描件也支持），把银行账号、税号等敏感信息遮盖掉，再交给大模型（DeepSeek / 通义千问等）提取服务范围、每一项金额、付款计划、里程碑和关键条款。提取结果经人工复核确认后入库，可以随时查询、导出。

## 第一次使用

1. **确认已安装 Python 3.10 – 3.14**（推荐 3.13；Python 3.15 太新，部分组件还不支持，可以和 3.13 同时安装，启动脚本会自动选用 3.13）
   如果没有安装，到 <https://www.python.org/downloads/> 下载，安装时勾选 **Add python.exe to PATH**。
2. **双击 `start.bat`**
   第一次运行会自动创建独立的运行环境并安装依赖，需要联网，大约 3–5 分钟。以后每次启动只需几秒。
3. 浏览器会自动打开 <http://localhost:8000>。
4. **第一次打开会要求创建管理员账号**，填用户名、姓名、密码后进入系统。
5. 进入 **设置**：
   1. 选择服务商（DeepSeek / 通义千问）。
   2. 填入 API Key。
   3. 点 **测试连接**，成功后点 **保存**。
6. 回到 **合同台账**，点 **上传合同**。

> 关闭黑色命令行窗口，系统就会停止。

## 用户、角色、部门与审计

在 **用户与权限** 页面管理，分四个标签页：

**用户**：添加同事，设置姓名、工号、部门、岗位、角色。可以重置密码、停用账号，也可以单独设置某人的 AI 每日用量上限。
- 用户名只能用英文字母和数字（3–32 位），不能有空格或符号；不区分大小写，不能重复。
- 工号必填，只能包含字母、数字和"-"，全系统唯一（不区分大小写）。
- 密码至少 10 位，必须同时包含字母和数字。

**待审核**：没有账号的同事可以在登录页点 **注册账号** 自行申请，提交后页面显示"已发送管理员审核"。申请在这里出现（导航栏有红色数字提醒），管理员点 **通过** 时同时分配角色、部门和岗位，之后对方才能登录；点 **拒绝** 会删除申请。审核前对方登录会提示"正在等待管理员审核"。同一 IP 每小时最多提交 5 次申请。

**角色与权限**：每个角色能做哪些操作，用勾选框设置，勾上立即生效。可以授权的操作有：

| 权限 | 说明 |
|---|---|
| 上传合同 | 上传 PDF / Word |
| 修改合同内容 | 修改 AI 提取结果、备注、合同状态 |
| 确认复核 | 确认 / 撤销复核 |
| 重新识别与分析 | 重新识别文字、重新 AI 分析 |
| 调整合同部门 | 修改合同的可见部门 |
| 删除合同 | 永久删除合同及原件 |
| 下载原件 | 下载原始文件（在线查看不受限） |
| 导出 Excel | 导出合同、明细、付款表 |
| 登记付款 | 登记付款节点是否已付款，上传、删除付款凭证，添加付款节点 |
| 使用 AI 助手 | 向 AI 提问 |
| 查看审计日志 | 非管理员只能看到自己可见合同的记录 |

- 内置三个角色：管理员（固定拥有全部权限）、编辑、只读。也可以新建角色，比如只能复核的"审核员"、只能上传的"录入员"。
- 用户管理、AI 设置、备份只有管理员能操作。

**部门**：合同按部门划分可见范围。
- 合同可以属于一个或多个部门，只有这些部门的人能看到。不属于任何部门的合同，全公司可见。
- 新上传的合同默认归上传人所在的部门，有"调整合同部门"权限的人可以修改。
- 部门可以开启"可查看所有合同"，适合财务、审计等部门。管理员始终能看到全部合同。
- 部门划分对所有功能生效：合同台账、搜索、详情、原件、导出、审计日志，以及 AI 助手能查到的范围。

**登录**
- 登录和注册都要输入图片验证码（4 位字母数字，不区分大小写）。看不清可以点图片换一张；输错一次就会换新的。
- 关闭系统的所有网页后再打开，需要重新登录；刷新页面、或者在已登录时另开一个标签页，不需要重新登录。
- 30 分钟内没有打开系统的任何页面，登录会自动失效；一次登录最长 12 小时。

**审计日志** 记录谁在什么时间做了什么，修改操作会列出每个字段的原值和新值。合同详情页的 **修改记录** 标签会显示这份合同的完整历史。已复核的合同被再次修改后，会自动退回 **待复核**。

## 付款跟踪

- **付款节点**：AI 分析合同时会把付款条款（比如"签约后预付 30%"）自动列成付款节点，在合同详情的 **付款与里程碑** 标签里可以看到。没有识别出来的节点可以手动添加。
- **登记付款**：点节点右边的 **登记**，选"已付款"，填实付金额和付款日期（会自动带出计划金额和当天日期），再上传银行回单等付款凭证。凭证支持 PDF、图片、Word、Excel，单个不超过 20 MB。
- **计划日期**：可以给节点填一个计划付款日期。过了这个日期还没付款的节点会标红显示为"已逾期"。
- **付款跟踪页面**：左侧导航的 **付款跟踪** 列出所有你能看到的合同的付款节点，可以按未付款、已逾期、30 天内到期、已付款筛选。合同台账里的 **付款进度** 列显示每份合同"已付 / 共几个节点"。
- **重新 AI 分析不会冲掉登记**：已经登记过、上传过凭证或手动添加的节点会保留；没人动过的节点才会按新的分析结果更新。
- 所有登记、凭证的上传和删除都会记入审计日志和合同的修改记录。导出 Excel 的"付款"表也包含付款状态。

## AI 助手

左侧导航进入 **AI 助手**，用法和 Claude 网页版类似：
- **会话**：可以新建、搜索、重命名、删除会话，每个人的会话只有自己能看到，管理员也看不到。
- **怎么回答**：AI 只在你有权查看的合同里查找，并标注出处，比如 `NZPI-0913-XZQ p.6`。点击出处会直接打开合同，翻到原文对应页。
- **只问某几份合同**：在合同详情页点 **问 AI**，或者新对话开始前选好合同。
- **只读**：AI 不能修改任何数据。发给 AI 的原文都已遮盖银行账号、税号等信息。
- **用量上限**：管理员可以在 **设置 → AI 助手** 里设置每人每天的提问次数和 tokens 上限、全系统每天的上限，以及每人每分钟的提问次数，并查看每个人的用量。

## 让同事也能访问

双击 `start_lan.bat`（不要用 `start.bat`）启动。窗口里会显示一个 `http://192.168.x.x:8000` 这样的地址，同事在浏览器里打开这个地址即可访问。

- 第一次启动时，Windows 防火墙可能会弹窗询问，选择 **允许（专用网络）**。
- 这种方式是普通 HTTP，密码在网络上不加密传输，只建议在公司内网使用；放到云服务器上请用 `deploy/install.sh`（带 HTTPS）。

## 使用流程

| 步骤 | 说明 |
|---|---|
| 上传 | 支持 PDF（含扫描件）、Word (.docx)，可以多选、拖拽；同一份文件重复上传会自动跳过 |
| 自动处理 | 依次是：识别文字（扫描件用本机 OCR）→ 遮盖敏感信息 → AI 提取。一份 20 页的扫描件大约需要 1–2 分钟 |
| 复核 | 打开合同，对照右侧原件核对，每个字段旁边的 `p.3` 可以跳到原文对应页。有错误点 **编辑** 修改，核对无误后点 **确认复核** |
| 搜索 | 在 **合同台账** 的搜索框输入关键词（中英文都可以）。结果按合同分组，每份合同下列出命中的金额明细项、条款，以及原文命中的页。点击任意一条，会直接打开合同对应的位置，右侧原件同时翻到那一页 |
| 导出 | **导出 Excel** 包含合同、明细、付款三个工作表 |

**金额明细** 页面顶部会自动核对“各项明细之和”是否等于“合同总额”，对不上会标红提示。

## 部署到云服务器（Ubuntu 24.04，推荐）

部署后，大家在任何地方都可以通过 `https://服务器IP`（或域名）访问。系统作为后台服务运行，开机自动启动，出问题会自动重启。

**准备工作**
1. 云服务器重装为 **Ubuntu 24.04 LTS**，内存至少 2 GB。
2. 在云厂商控制台的**安全组 / 防火墙**里放行 **22、80、443** 端口。
3. 在 GitHub 生成一个只读令牌，用来下载私有仓库：
   - 路径：GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
   - Repository access 选 **Only select repositories → contract-management-system**。
   - Permissions → Repository permissions → **Contents: Read-only**。

**安装（SSH 登录服务器后，以 root 执行）**
```bash
git clone https://github.com/Chitoge520/contract-management-system.git /opt/contract-register
#   Username: Chitoge520    Password: 粘贴上面生成的令牌
git -C /opt/contract-register config credential.helper store   # 记住令牌，以后更新不用再输
bash /opt/contract-register/deploy/install.sh                   # 不用域名：直接用服务器 IP + HTTPS
bash /opt/contract-register/deploy/backup.sh --install          # 每天 02:30 自动备份，保留 14 天
```
如果以后有了域名，把 A 记录指向服务器，再运行 `bash /opt/contract-register/deploy/install.sh 你的域名 你的邮箱`，就会自动换成正式的 Let's Encrypt 证书。

脚本依次完成：
- 安装依赖
- 创建专用运行账号
- 注册系统服务
- 配置 Nginx 和 HTTPS
- 开启防火墙

完成后会显示访问地址，例如 `https://203.0.113.10`。打开后创建管理员账号，在 **设置** 里填写 API Key。

**关于"不安全"提示（只在用 IP 访问时出现）**
没有域名时，证书由服务器自己签发。数据依然是加密传输的，只是浏览器不认识这个签发者，所以会提示"不安全"。有两种处理办法：
- **简单：** 点 **高级 → 继续访问**。
- **彻底去掉提示（每台电脑做一次）：**
  1. 浏览器打开 `http://服务器IP/server-cert.crt`，下载证书。
  2. 双击证书 → **安装证书**。
  3. 选 **本地计算机** → **将所有的证书都放入下列存储** → 浏览 → **受信任的根证书颁发机构** → 完成。
  4. 重启浏览器。

**日常维护**
| 做什么 | 命令 |
|---|---|
| 更新到最新版本 | `bash /opt/contract-register/deploy/update.sh` |
| 查看运行状态 | `systemctl status contract-register` |
| 查看日志 | `journalctl -u contract-register -f` |
| 重启 | `systemctl restart contract-register` |
| 手动备份 | `bash /opt/contract-register/deploy/backup.sh`（备份在 `/var/backups/contract-register`） |

**安全措施**
- 只开放 22 / 80 / 443 端口；80 端口只用于跳转到 HTTPS 和下载证书，登录 Cookie 只通过加密连接传输。
- 同一 IP 连续输错密码 8 次，锁定 15 分钟。所有登录和失败尝试都记录在审计日志里，包含 IP。
- 系统账号密码至少 10 位，且需同时包含字母和数字。
- 程序用一个没有登录权限的专用账号运行，只能写自己的 `data` 目录。
- 服务器安装了 fail2ban：同一 IP 对 SSH 输错 5 次封禁 1 小时，屡犯者封禁时间加倍。
- 建议在阿里云开启**自动快照**（备份存在服务器之外），并把安全组的 22 端口限制为自己的 IP。

## 部署到另一台内网电脑（Windows）

这台电脑会成为大家共用的系统，同事都在浏览器里访问它。它需要保持开机，并且能上外网（第一次安装依赖、调用 AI 都要用到）。

1. **安装软件**
   - Python 3.13（3.10–3.14 均可，**不要只装 3.15**）：<https://www.python.org/downloads/>，安装时勾选 **Add python.exe to PATH**。
   - Git：<https://git-scm.com/download/win>，安装时一路默认即可。
2. **下载代码**：在想放程序的位置（例如 `D:\`）空白处右键 → **在终端中打开**（或打开 Git Bash），运行：
   ```
   git clone https://github.com/Chitoge520/contract-management-system.git
   ```
   仓库是私有的，第一次会弹出 GitHub 登录窗口，用 Chitoge520 账号登录授权即可。
3. **启动**：进入 `contract-management-system` 文件夹，双击 **`start_lan.bat`**。第一次会自动安装依赖（3–5 分钟）。Windows 防火墙弹窗时选择 **允许**。
4. **初始化**：浏览器打开后创建管理员账号，然后在 **设置** 里填写 AI 的 API Key，在 **用户管理** 里给同事建账号。
5. **告诉同事地址**：黑色窗口里显示的 `http://192.168.x.x:8000` 就是同事访问的地址。
6. **开机自动启动（可选）**：按 `Win + R`，输入 `shell:startup` 回车，把 `start_lan.bat` 的**快捷方式**放进打开的文件夹。

**以后更新版本**：双击 **`update.bat`** 下载最新代码，然后关掉黑色窗口，重新双击 `start_lan.bat`。`data` 文件夹里的合同、账号和设置不受影响。

**注意**：每台电脑的 `data` 文件夹相互独立。笔记本上的数据不会自动出现在服务器上；如果需要迁移，用 **设置 → 下载备份**，把备份里的 `data` 文件夹放到服务器的程序目录。

## 数据与隐私

- 所有数据都在程序目录下的 `data` 文件夹里：
  - `data/contracts.db`：数据库，单个文件
  - `data/files/`：合同原件
  - `data/config.json`：AI 设置，包含 API Key
- 发给 AI 的只有遮盖后的文本。在合同详情的 **原文 → 发送给 AI 的文本** 里，可以看到实际发出去的内容。
- 遮盖的内容包括：银行名称/地址/账号、SWIFT/CNAPS/IBAN、税号、VAT 号、公司注册号、9 位以上的长数字串。合同金额（如 696,000）不会被遮盖。

## 备份与迁移

- **备份**：进入 **设置 → 下载备份**，会得到一个 zip 文件；也可以直接复制整个 `data` 文件夹。
- **恢复 / 换电脑**：
  1. 把整个程序文件夹复制到新电脑（`.venv` 文件夹可以不复制）。
  2. 把备份里的 `data` 文件夹放回程序目录。
  3. 双击 `start.bat`。
- **数据库自动升级**：新版本的程序如果调整了数据库结构，启动时会自动升级，不需要手动操作。升级前会把旧数据库复制一份到 `data/backups/`，文件名里带有升级前的版本号和时间。升级成功、系统用了几天没有问题后，这些文件可以删掉。
  - 如果升级后需要退回旧版本：停止系统，把这个备份文件改名为 `contracts.db`，替换 `data` 文件夹里的同名文件，再启动旧版本。

## 常见问题

- **安装依赖失败**：公司网络可能需要代理。可以先在命令行设置 `set HTTPS_PROXY=http://代理地址:端口`，再运行 `start.bat`。
- **AI 提取失败**：在合同详情里能看到具体的错误原因。修正设置后，点右上角 **⋯ → 重新 AI 分析**。
- **提示“输出被截断”**：合同明细很多时会出现。在设置里把“最大输出 tokens”调大（DeepSeek 最大 8192，qwen-plus 可以设到 16384），或者换用 `qwen-max`。

```
push.bat        把本机改过的代码上传到 GitHub
requirements.txt
```
